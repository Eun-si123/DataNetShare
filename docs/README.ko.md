# DataNet Share 사용 안내 · 5.1-dev

이 저장소는 [Eun-si123/DataNetShare](https://github.com/Eun-si123/DataNetShare) 유지보수 포크입니다. 휴대폰의 모바일 데이터를 Wi-Fi Direct·USB·사설 Wi-Fi를 통해 **인증이 있는 SOCKS5 프록시**로 공유합니다. 안드로이드 전체 앱 트래픽을 받는 내장 수신 VPN도 있지만 **실험 기능**입니다.

**통신사 테더링 제한 우회, 모든 게임·앱의 호환성, VPN 프라이버시는 보장하지 않습니다.** 자동 소켓 테스트와 APK 빌드만으로 실제 휴대폰 간 안정성 검증이 끝나는 것은 아닙니다.

## 설치

**간편 다운로드:** [GitHub Releases](https://github.com/Eun-si123/DataNetShare/releases)에서 `v5.1-dev.6` **Pre-release(시험판)**를 선택하세요. **Assets** 아래의 `DataNetShare-5.1-dev.5-debug.apk`를 직접 내려받아 설치하면 됩니다. 'Source code' ZIP이 아니라 APK를 받아야 합니다. `SHA256SUMS.txt`는 파일 무결성 확인용입니다. Android 8.0 이상에서 사용 가능합니다.

**주의:** 현재 공개 시험판은 CI에서 임시로 생성한 개발용 키로 서명돼 있어 향후 APK 업데이트가 서명 차이로 거부될 수 있습니다. 그 경우 삭제 후 재설치가 필요하며 앱 설정이 사라집니다. 실기기 안정성 검증을 완료한 정식 버전이 아닙니다.

**개발 빌드:** 별도로 [GitHub Actions](https://github.com/Eun-si123/DataNetShare/actions/workflows/android-ci.yml)의 성공한 실행에서 `datanetshare-debug-apk` 파일을 다운로드·압축 해제하여 `app-debug.apk`를 설치할 수도 있습니다. 해당 CI 파일은 보관 기간 후 만료됩니다.

개발판 패키지는 **`com.datanet.share.dev`**라 기존 앱과 함께 설치할 수 있습니다. 원본 Releases의 APK는 이번 개선 코드를 포함한 빌드가 아닐 수 있습니다. 서로 다른 빌드 환경의 디버그 서명은 다를 수 있어 업데이트 설치가 거부될 수 있습니다. 반복 설치에는 같은 환경의 서명 키를 쓰는 편이 좋습니다.

## 보내는 휴대폰

1. 모바일 데이터를 켜세요.
2. **Wi-Fi Direct로 공유:** Wi-Fi를 켜고 버튼을 누르세요. Android 13 이상은 근처 Wi-Fi 기기 권한을 허용하고, Android 8~12는 위치 권한과 위치 서비스를 켜야 할 수 있습니다.
3. **USB / Wi-Fi로 공유:** USB 테더링이나 같은 사설 네트워크를 준비하고, 주소를 새로고침해 실제 USB·Wi-Fi 주소를 선택하세요. 그 주소에만 프록시가 열립니다.
4. 연결 정보에서 **주소, 포트 8282, 아이디 `datanet`, SOCKS5 비밀번호**를 확인하세요. 비밀번호는 공유를 다시 시작할 때 바뀝니다.

Wi-Fi Direct는 **Wi-Fi 비밀번호**로 네트워크에 먼저 연결한 뒤, 별도의 **SOCKS5 비밀번호**로 프록시에 접속합니다. 두 비밀번호를 헷갈리지 마세요. 그룹 주소는 기기마다 달라질 수 있으므로 `192.168.49.1`만 믿지 말고 화면에 나온 주소를 쓰세요.

기본은 **모바일 데이터만** 사용하며, 모바일망을 못 잡으면 다른 경로로 몰래 우회하지 않습니다. 기존 VPN을 이용하려면 시작 전에 **안드로이드 기본 경로 사용**을 켜세요. 이 옵션에는 VPN 킬 스위치가 없고, VPN 제외 앱 설정이나 연결 해제로 인해 VPN 밖으로 통신할 수 있습니다.

## 휴대폰끼리 QR코드로 연결 (5.1-dev.3)

1. **송신 휴대폰:** 모바일 데이터와 Wi-Fi를 켜고 `Wi-Fi Direct로 공유`를 시작한 뒤, 연결 정보의 **연결 QR코드 표시** 버튼을 누릅니다. USB/사설 Wi-Fi 공유 모드도 가능합니다.
2. **수신 휴대폰:** 앱에서 **송신기 QR코드 스캔 (카메라)** 버튼을 눌러 송신기의 QR을 스캔합니다. 카메라 권한이 필요합니다.
3. 송신 IP, 포트, SOCKS5 비밀번호가 자동 입력됩니다. Wi-Fi Direct 정보도 있다면 **Wi-Fi 비밀번호 복사 → Android Wi-Fi 설정 열기**를 눌러 네트워크에 접속한 뒤 앱으로 돌아옵니다. 일부 기기는 별도의 Wi-Fi Direct 메뉴에서 연결해야 합니다.
4. **수신 VPN 시작** 버튼을 눌러 Android VPN 권한을 승인합니다. 전체 앱 호환성은 아직 실험 단계입니다.

**보안:** QR에는 프록시 및 Wi-Fi 비밀번호가 평문으로 들어갑니다. 신뢰하는 상대에게만 보여 주세요. **새 공유 세션마다 QR이 바뀌지만, 한 번 스캔하면 소진되는 코드는 아닙니다.** QR을 촬영한 사람은 해당 세션이 종료될 때까지 연결할 수 있습니다. 세션을 중지하고 다시 시작하면 새 SOCKS5 비밀번호가 생성됩니다. QR 정보는 클라우드나 앱 설정 파일에 저장되지 않습니다.

## 받는 기기

**컴퓨터·외부 클라이언트:** SOCKS5 아이디/비밀번호 인증과 원격 DNS를 지원하는 프로그램에서 송신 화면의 정보를 입력하세요. OS나 브라우저의 기본 프록시 설정은 인증이나 모든 앱 트래픽을 지원하지 않을 수 있습니다. curl 연결 확인 예:

```sh
# PHONE_IP를 송신 화면의 주소로 바꾸세요. 세션 비밀번호는 프롬프트에서 입력합니다.
curl --socks5-hostname PHONE_IP:8282 --proxy-user datanet https://example.com/
```

**안드로이드 내장 수신 VPN:**

1. 송신 휴대폰의 네트워크에 연결하고, 인터넷이 없다는 안내가 나와도 연결을 유지하세요.
2. 수신 화면에 송신 IPv4 주소·포트·SOCKS5 비밀번호를 입력하세요.
3. **수신 VPN 시작**을 누르고 시스템 권한을 허용하세요. 먼저 주소와 인증을 점검하고 나서 VPN 경로를 만듭니다.
4. 진단 메뉴에서 UDP 도달성 테스트를 할 수 있습니다. 외부 Google STUN 서버에 접속하는 검사이므로 실패했다고 모든 UDP 통신이 안 되는 것은 아닙니다.

내장 수신기는 IPv4 TCP·UDP용이며 IPv6·ICMP·IP 조각 재조립은 지원하지 않습니다. 게임·영상·장시간 연결의 기기별 실사용 검증이 남아 있으므로, 넓은 호환성이 필요하면 검증된 SOCKS5 지원 외부 클라이언트를 이용하세요. iOS는 이 APK를 실행할 수 없으며, 인증을 지원하는 별도 클라이언트가 필요합니다.

## 네트워크 진단은 어디에 표시되나요? (5.1-dev.6)

송신 폰과 수신 폰에서 앱을 열면 **맨 위 ‘연결됨’ 상태와 전송 통계 바로 아래**에 **‘네트워크 진단 · 송신기 / 수신기’** 영역이 보여요. 이전에는 일부 UDP 접속 실패가 내부에서 무시되어 아무 오류도 뜨지 않을 수 있었지만, 이제 송신기 외부 연결 실패, TCP·UDP 연결 제한, UDP 설정 및 수신 오류, VPN 출력 혼잡의 누적 횟수를 표시합니다.

**‘진단 내용 복사 (비밀번호 제외)’** 버튼으로 IP, QR, SOCKS5/Wi-Fi 비밀번호, 접속 사이트 이름 없이 오류 유형과 횟수만 복사할 수 있어요. 수신 통계에는 **TCP attempts / connected**, **UDP attempts / associated**, **TUN drops**도 표시됩니다. 오류가 없어도 속도 측정이 0으로 멈추면 연결이 어느 단계까지 진행됐는지 살펴볼 수 있습니다.

송신 폰이 사용 중인 인터넷 출구는 사용자가 직접 모바일 데이터 공인 IP와 다른 Wi-Fi 공인 IP를 비교해 확인했습니다. 따라서 지금은 모바일 데이터가 아닌 Wi-Fi로 나가는 문제가 아니라 실험용 VPN의 TCP/UDP 호환성과 연결 처리에 집중합니다. **진단 기록이 없어도 통신이 정상이라는 보장은 없습니다.**

## 속도 측정 오류 및 TCP 수신기 보강 (5.1-dev.5)

브라우저에서 FAST.com이 간헐적으로 `ERR_CONNECTION_RESET`을 표시하고 Ookla에서 `LATENCY TEST ERROR`가 발생한 실기기 사례를 조사했습니다. 이번 버전에서는 수신기 TCP 연결 응답에 **MSS 1200**을 명시하고, VPN TUN 인터페이스 출력 큐가 일시적으로 가득 차더라도 제한적으로 대기·재시도하도록 바꿨습니다.

이는 성능·안정성 개선을 위한 수정이지 속도 측정이 정상화됐다고 검증된 결과는 아닙니다. **HTTP/3/QUIC, IPv6, IP 단편화, 대량 동시 연결** 지원에는 여전히 한계가 있습니다. 문제가 반복되면 두 폰의 `Last upstream error` 및 `Last TCP error` 문구를 비교하세요. 먼저 단순한 IPv4 HTTPS 웹페이지를 열고, 그다음 속도 테스트로 비교하면 실패 범위를 좁히기 좋습니다.

## 브라우저 ERR_CONNECTION_RESET 및 인터넷 출구 확인 (5.1-dev.4)

- **송신 폰이 다른 Wi-Fi에 연결돼 있어도** 기본값(안드로이드 기본 경로 사용 꺼짐)에서는 모바일 데이터만 목적지 연결에 이용합니다. 모바일 데이터가 켜져 있지 않거나 Android가 별도의 모바일 네트워크를 확보하지 못하면 송신 SOCKS5에 접속한 뒤에도 웹사이트 TCP 접속은 실패할 수 있습니다.
- 다른 Wi-Fi의 인터넷을 쓰고 싶다면 **송신 중지 → 안드로이드 기본 경로 사용 켬 → 다시 공유**를 시도하세요. 그 뒤 송신 화면의 **Android default route: Wi-Fi / mobile data / VPN** 표시를 확인하세요. 기본 경로는 OS 선택이며, Wi-Fi Direct를 켜면 제조사에 따라 기존 Wi-Fi 연결이 끊기거나 경로가 바뀔 수 있습니다.
- **송신 화면**에서 `Mobile data`는 실제 앱의 모바일 네트워크가 확보된 상태, `Waiting for mobile data`는 확보되지 않은 상태입니다. 최근 실패가 있으면 `Last upstream error`가 표시됩니다. **수신 화면**에는 TCP 소켓 실패나 재전송 오류를 `Last TCP error`로 표시합니다. 이 문자열은 실제 IP, DNS 이름, 비밀번호를 남기지 않습니다.
- 기본 모드에서 모바일 네트워크가 없으면 SOCKS5 **network unreachable (3)** 응답이 나가며, 수신 앱이 TCP를 재설정할 수 있습니다. 따라서 브라우저에서 `ERR_CONNECTION_RESET`만 보이는 경우 반드시 양쪽 앱의 상태 문구를 확인하세요.
- 다른 Wi-Fi를 송신 인터넷으로 이용하는 모드는 VPN 킬 스위치가 없고, Android의 기본 경로 변경 시 인터넷 출구도 바뀔 수 있으므로 모바일 데이터 사용량과 실제 출구 IP를 직접 확인하세요.
- 자동화된 큰 TCP 다운로드 테스트는 2 MiB 이상의 데이터 무결성을 확인하지만, 브라우저의 실제 Speedtest, HTTP/3/QUIC, IPv6, VPN/기기별 호환성을 보장하지는 않습니다.

## 종료와 문제 해결

- **`Sender check failed: Could not protect sender socket` 오류:** `5.1-dev.1`에서 보고된 소켓 초기화 순서 문제를 `5.1-dev.2`에서 수정했습니다([PR #3](https://github.com/Eun-si123/DataNetShare/pull/3)). 새 버전 설치가 안 된다면 기존 **개발판**을 제거하고 재설치해야 할 수 있습니다(앱 설정 초기화). 실제 기기에서 오류가 사라지는지 추가 검증이 필요합니다. 수정판에서도 반복되면 Android VPN 권한 및 다른 VPN·항상 켜기 VPN 충돌 여부를 확인하세요.
- **연결 중지** 또는 알림의 **Stop**으로 종료한 뒤 모드를 바꾸세요. 앱을 다시 열어도 진행 중인 상태를 표시합니다.
- 인증 실패 시 Wi-Fi 암호가 아닌 SOCKS5 암호인지 확인하세요. 재시작하면 새 암호가 생깁니다.
- Wi-Fi Direct가 BUSY면 다른 공유 앱이나 기존 그룹을 종료한 뒤 다시 시도하세요. 이 앱은 다른 앱의 그룹을 강제로 제거하지 않습니다.
- USB·Wi-Fi 주소가 바뀌면 중지 → 주소 새로고침 → 주소 선택 → 다시 시작하세요.
- 모바일 데이터가 끊기면 기본 모드의 인터넷 연결은 실패합니다. 프록시가 실행 중이라는 표시가 인터넷 도달성을 보장하지는 않습니다.
- Android의 다른 VPN 실행, 항상 켜기·VPN 외 차단, 제조사 절전 설정은 수신 연결에 영향을 줄 수 있습니다.

SOCKS5 비밀번호는 통신을 암호화하지 않습니다. USB나 신뢰하는 사설 Wi-Fi에서 쓰고, 연결 정보를 외부에 공개하지 마세요. 비밀번호는 저장하지 않으며, 사용자가 복사하면 클립보드에 들어갑니다.
